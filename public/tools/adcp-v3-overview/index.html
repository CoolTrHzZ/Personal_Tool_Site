Agent Development Control Plane 不是另一个编码模型，也不是把一堆 rules 塞进全局目录。 它是一层落在项目旁边的开发控制平面：保存项目知识、锁定模块版本、约束执行流程、统一 Codex / Cursor / Claude 等入口， 让不同模型、不同设备、不同开发阶段都围绕同一套项目事实继续工作。

The problem

真正的问题不是“模型不够强”

大型或长期项目里，更常见的问题是：模型每次都要重新理解项目、全局 Skill 干扰当前仓库、工具之间规则不同、开发做到一半换设备就丢上下文。

01 / CONTEXT

上下文不断重建

项目背景、架构、约束、当前任务和验收标准散落在聊天记录、README 和人的脑子里。

02 / POLLUTION

全局 Skill 污染项目

同一个全局规则未必适用于所有项目；更新一个 Skill 还可能悄悄改变已经稳定的项目行为。

03 / TOOLING

不同工具各说各话

Codex、Cursor、Claude 或本地模型读取入口不同，项目规则容易出现重复、漂移和冲突。

Design principles

ADCP 的四条设计原则

L1Local-first项目控制信息优先落在项目本地，能随仓库迁移，也能离线理解。
LKProject Locked模块进入项目后显式锁定；Runtime 更新不应该静默改写项目行为。
OVLocal Override开发者可以在本机覆盖模块和模型配置，而不污染团队仓库。
AGAgent Neutral控制平面不绑定单一编码 Agent，适配层负责对接不同开发工具。
Architecture

v3.0：从“规则目录”升级为分层控制平面

Modular skills

Skill 不再“全局安装后听天由命”

v3 的关键变化，是把能力做成项目可锁定的模块。模块可以来自内置能力，也可以逐步扩展为外部仓库能力；安装后记录版本/内容哈希，发生漂移时可被 doctor 检出。

Delivery workflow

让 Agent 不是“写一点就停”，而是推进到可验收

ADCP 把项目从初始化、知识加载、任务执行到验收与交付串成生命周期。Full Delivery 模块强调完整实现、测试、验收和状态沉淀，而不是只输出零散代码片段。

01INIT识别空项目 / 已有项目 / capsule，建立控制平面。
02LOAD读取项目知识、架构、约束、当前任务与模块。
03PLAN绑定任务范围、实现边界和验收标准。
04BUILD按项目规则开发，必要时由多个 Agent/工具接力。
05VERIFY运行测试、doctor、acceptance gate，检查结果而非只看过程。
06FINALIZE更新状态、报告与可恢复信息，进入用户验收。
Terminal State 的重点不是“模型说做完了”，而是：项目状态、验证结果和交付物都满足可检查的完成条件。

DAY 60升级 ADCP
先更新全局 Runtime；项目继续保持原状。确认需要新架构时，再显式执行 project upgrade。

          

        

      

    


    

      

        Model adapter
        
模型也不应该绑死在框架里

        
ModelAdapter 提供 provider-neutral 接口，目前可对接 OpenAI-compatible、Ollama 和 Mock。API Key 配置只记录环境变量名，避免把密钥直接写进项目文件。

        

          
OAOpenAI-compatible对接兼容 API 的云端或本地推理服务。

          
OLOllama适配本地模型运行环境，便于个人开发与实验。

          
MKMock用于离线测试、自动化测试和无需真实推理的流程验证。

          
ENVSecret by env项目只保存环境变量名，不把 API Key 明文固化进仓库。

        FAQ
        
常见问题

        

          

            我已经有一个项目了，接入 ADCP 会不会覆盖现有代码？
            
设计上不会把已有业务项目当成空项目重建。已有项目走知识初始化流程，保留业务代码与已有项目知识，并添加 ADCP 所需的控制平面文件和适配入口。

          

          

            为什么不把所有 Skill 全局安装一次？
            
因为不同项目需要的开发规范和工具能力并不相同。项目级锁定可以让“当前项目正在依赖什么”变成明确事实，同时避免全局更新给稳定项目带来隐性行为变化。

          

          

            同一个项目里，我能有自己的本地配置吗？
            
可以。v3 引入 .adcp-local 作为开发者本地覆盖层，可放 workspace、model.json 和本地模块覆盖。它的优先级高于项目模块，适合个人环境差异和实验配置。

          

          

            升级 ADCP 后，所有项目都会立刻升级吗？
            
不会。全局 Runtime 和项目升级是两个动作。更新 Runtime 不等价于迁移项目；只有显式运行 agent upgrade PROJECT 才会升级该项目的结构或模块状态。

          

          

            ADCP 是否只能配合 Codex 使用？
            
不是。--platform all 会保留 Codex + Cursor 等兼容面，并通过 AGENTS.md、工具目录和 adapter 机制把同一套项目事实暴露给不同编码 Agent。
