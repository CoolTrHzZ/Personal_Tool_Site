## 已保存、内存值与跨标签

`personal-storage.ts:1–15` 的模块内 pending Map 优先于 localStorage 读取。写成功移除 pending，写失败保留 raw 并抛错；关闭／刷新页面会丢失未持久化的模块内存。`WorkspacePanel.tsx:11–79` 校验初始记录，异常时保留原存储而显示 fallback 与错误。保护状态下的普通操作不覆盖原存储；明确重试写当前已接受值。

待办与计时的函数式更新先读取最新记录（`:51–65`），覆盖存储事件尚未到达时的竞态；计时还核对当前按钮意图。存储事件遇到 pending 会保留本页修改并提示先备份再重试；异常其它标签记录不会清空当前视图。普通便笺编辑传入字符串，不走函数式重读，因而不是普遍的跨标签冲突检测或协作合并机制。Home视图偏好没有订阅跨标签的 `devos-home-view` 更新。

“会话中未保存修改可抢救”应限定为已经进入个人 pending Map 的有效记录；尚未添加的待办输入、未通过校验的超限便笺不在其中。主题、动效、首页视图的直接写失败仅保留各自React状态（`Header.tsx:46–48`、`Layout.tsx:89–92`、`HomePage.tsx:51–54`），没有进入该Map，不能扩大承诺为任意页面内存状态均进入备份。

## 恢复格式、合并与失败限制

- 外层保持 `kind: "devos-personal-data"`、`version: 1`、字符串 `exportedAt`、`entries`（白名单键到原始存储字符串）。时间是导出时间，不是每条记录的原修改时间；导入只检查它为字符串。UI文件入口先按32MiB字节限制读取UTF-8文本，解析器另检查字符串长度（`tool-files.ts:3–12`、`PersonalDataPanel.tsx:27`、`personal-backup.ts:60–75`）。
- 正常可读取但没有记录时允许导出空entries；若存储不可读且没有任何可抢救项则报错，不下载空文件假装成功。null表示无记录，不等读取失败。
- `unavailableKeys` 和兼容的 `unreadableKeys` 都须为无重复的白名单字符串数组，不能和entries重叠；同时提供时集合必须相同，归一后使用前者。读取失败不是空记录，不会借缺失清单删除目标。现代AI任务raw可读取且非空时跳过旧草稿读取；这一步不验证现代任务内容。
- 合并保留当前计时与偏好；便笺拼接，待办／AI同ID但不同内容保留两份（给副本新ID）；收藏／置顶取并集，最近工具／搜索只保留合并后前8条。CFG保留本机草稿、合并版本，外来非空且未重复草稿作为版本；越过既有数量／内容上限会拒绝，不截断以伪装成功。
- 旧AI单草稿转为现代任务列表参与恢复。若已有现代列表或文件标记该列表缺失，替换被拒，只能合并；无现有列表且无缺失标记时允许首次迁移。此转换是“仅含项目”的明确例外映射，不代表一个草稿可替换多个已有任务；旧存储键不因此自动删除。
- `preparePersonalImport:131–147` 同时捕获可见值（含pending）及持久值；`applyPersonalImport:153–158` 在任何写入前比较两者，变化则要求刷新预览。比较覆盖计划涉及的键，不是全库锁，也不保证另一个标签在检查与逐键写入之间无法变化。
- 写入顺序执行，失败反向尝试回滚已写项。回滚也失败时，把原可见值（包括null）放入pending，显示“部分存储无法恢复”并要求立即备份；底层存储可能仍部分改变。这是尽力恢复与抢救，不是事务、磁盘备份或持久回滚保证。成功才清对应pending并发 `devos:personal-data-restored`；主题／动效／首页偏好按UI提示刷新后应用。
- `revision` 在新文件、取消及卸载时变化，拒绝迟到读结果；`modeRef` 让完成读取使用当前模式。读取本身未收到AbortSignal，不应把忽略旧结果说成物理终止解码。取消就绪预览只清本次导入状态，不回滚此前已确认恢复或下载。

## 基线审查确认的呈现缺口与准确边界

1. **读取中的导入无状态或取消入口。** 将真实组件的 `readTextFile` 合成为尚未resolve的Promise，触发文件input后，预览、status／aria-busy、取消及确认按钮均不存在（`PersonalDataPanel.tsx:23–27,45`）。用户无法判断正在读取，也不能通过取消按钮作废当前读取。相同ReactDOM探针确认另选文件后旧结果被忽略、就绪预览取消不写存储，因此不是已有revision失效。最窄后续建议是补可见读取状态与仅作废当前读取结果的显式取消；不改变解析／恢复策略，也不宣称中止底层读取。本次不实现。
2. **前后预览是摘要，不是内容差异。** 真实组件对便笺 `abc` → `xyz` 的替换显示“3 字符 → 3 字符”，未展示正文；确认前零写入，明确确认后写入准确的 `"xyz"`。这是 `describePersonalEntry:32–42` 的数量／名称摘要合同，不是写错数据；不能据此宣称已经让用户核对逐字符变化。若未来需要内容差异预览，应另行限定敏感正文的显示范围。
3. **完整可读不等可恢复有效。** 在隔离存储放入便笺raw `bad-json`，真实 `exportPersonalData` 仍保留原raw、不列未读项；真实 `parsePersonalBackup` 拒绝这份文件。当前导出未执行 `checkEntry`，因此会保存可读损坏原文，不能保证该文件能原样恢复。最窄后续建议是保留抢救原文并明确标注校验状态，不能静默剔除损坏记录或把恢复失败说成成功。本次未改格式、导出或导入行为。
