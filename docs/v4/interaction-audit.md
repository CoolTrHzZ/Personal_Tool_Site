# 交互体验审计 · 2026-09-08

延续现有黑色主调和静态 GitHub Pages 架构，本轮针对前台浏览、个人工作区和本机 Admin 的实际操作问题进行修复。

| 问题 | 改进 |
| --- | --- |
| 删除或失效的筛选值仍在 URL 中，控件却显示“全部” | 收藏、笔记、导航、桌面工具、CFG、工具目录明确显示失效条件；有筛选时始终提供清除按钮。 |
| 输入 `all`、`default` 会被当成默认值清空 | 搜索词按原文保留；自定义标签、语言、分类及关联项目的 `all` 值也可以单独筛选。 |
| 工具目录刷新、打开工具后返回丢失条件 | 搜索、分类、状态和排序保存在 URL；卡片与命令面板打开工具后，页内返回恢复原目录条件，适配 React 和静态 iframe 工具。 |
| 后台选择标签、分类、图标后焦点消失 | 重绘选择器时恢复焦点；标签候选和已选标签支持方向键、Home、End、Esc。 |
| 非法标签输入可能被外部保存按钮绕过 | 在可见输入框上进行原生表单校验；笔记保存、工具编辑和导入向导均检查有效性，纠正输入后继续。普通搜索词不会自动变成已选标签。 |
| 待办误删无法恢复，到达数量上限时草稿被清空 | 提供最近一次删除的撤销，恢复位置及完成状态；达到 1000 条上限时保留输入并说明原因。撤销只保留在当前工作区会话中。 |
| 其他标签页刚保存，当前待办操作可能基于旧列表覆盖内容 | 增加、完成、删除和撤销先读取最新有效记录；损坏或无法读取时暂停这次修改，已有未保存内容继续保留。 |
| 暂停计时后重复点击当前模式会重置进度 | 同模式点击保留暂停进度，切换模式或显式重置仍重新计时。 |
| 首页目录只滚动不移动键盘焦点，开启工作区后焦点落空 | 章节跳转聚焦目标，下一次 Tab 从该章节继续；开启工作区后定位并聚焦待办输入框。 |
| 修改结果或切换笔记时，旧复制请求的迟到反馈覆盖当前状态 | 结果变化、页面切换和连续复制只接受当前请求的反馈。 |
| 工具加载失败只有提示文字，没有恢复入口 | 增加刷新重试与返回原筛选列表按钮；通过模拟加载失败、恢复网络和刷新验证恢复链路。 |
