# 个人数据备份与存储受阻恢复

个人数据仅保存在当前浏览器，和 Admin 的公开站点备份分开管理。本功能不上传内容，不创建账户，不提供跨设备自动同步，也不改变网站访问权限。

## 正常备份

在首页切换到“我的工作区”，找到“个人数据”，点击“导出个人备份”。正常文件名为 `devos-personal-backup.json`，包含当前可读取的待办、便笺、计时、收藏、最近记录、搜索历史、AI 任务、CFG 草稿及版本、项目置顶与偏好。当前页面已保留但尚未写入浏览器存储的修改优先于旧存储值。

备份可能包含私人文本和配置，请保存在可信位置，不要作为公开站点内容上传。它不包含 Admin 账户、认证信息、站点文件或其他应用的数据。

## 存储读取被拒绝时

1. 不要刷新、关闭页面或清理站点数据。尚未保存的修改可能只存在当前标签页内存中。
2. 点击“导出个人备份”。单个项目读取失败不会再阻断其他项目的导出。
3. 若只能读取部分内容，会下载 `devos-personal-recovery.json`。页面明确提示“这不是完整备份”，列出未能读取的项目；文件也记录同一份缺失清单。
4. 检查下载文件是否保留了需要的内容。无法读取且不在当前会话中的数据不能凭空恢复，不会用空值冒充。
5. 保留当前页面，恢复浏览器对站点存储的访问后再次导出。能够读取全部项目时重新使用正常备份文件名，不再带缺失清单。

若没有任何可导出的内容且存储仍不可读，页面只提示错误，不会下载空文件并宣称备份成功。下载行为也可能受浏览器限制，请确认文件确实保存。

## 导入恢复备份

在可正常使用存储的浏览器打开工作区，选择“导入个人备份”。恢复备份的预览会再次列出缺失项目。核对预览后，选择合并或替换并确认：

- 合并遵循现有规则，保留当前内容，便笺拼接、不同任务保留、外来 CFG 草稿存为版本。
- 替换只处理文件实际包含的数据项。缺失项目和其他未包含的数据不会删除或清空。
- 旧版文件若只含一个 AI 草稿，不代表完整任务列表。本机已有 AI 任务，或文件标明任务列表缺失时，必须选择合并恢复；替换预览会拒绝执行。没有现有任务且未标记任务列表缺失时，仍可首次导入旧版草稿。
- 预览后本地数据发生变化时必须重新预览；写入失败仍按现有机制回滚，不将部分成功当作完成。

导入前建议另行导出当前浏览器的完整备份。取消导入不会修改数据；成功后刷新页面，确认记录仍可读取。

## 格式兼容性

备份继续使用 `kind: "devos-personal-data"`、`version: 1` 与 `entries`。完整备份格式不变；恢复备份另有可选 `unavailableKeys` 数组，记录读取失败的白名单数据项。该数组不是要删除或覆盖的内容，不能与 `entries` 中的项目重叠。导入拒绝未知、重复或非法的缺失项目。

导入同时兼容使用 `unreadableKeys` 的版本 1 恢复文件，并将它归一为 `unavailableKeys`。两种字段都必须是无重复的白名单字符串数组，且不能与实际内容重叠；若同时提供，两者必须表示相同集合，否则拒绝导入。重新导出继续使用 `unavailableKeys`，正常完整备份不包含缺失清单。可读取现代 AI 任务列表时，不再读取或标记已被取代的旧版草稿。

新版仍可导入既有完整备份。旧版虽只导入 `entries`，但不显示恢复备份的缺失警告；恢复操作建议使用提供此警告的版本。

## 本地验证与回退

使用 Node.js 22+，安装锁文件依赖后可执行：

```bash
npm ci
npx vitest run tests/personal-backup.test.js tests/personal-data-panel.test.js tests/tool-persistence.test.js
npx playwright test e2e/workspace-redesign-personal-data.spec.js --project=workspace --workers=1
npm run lint
npm run build
```

浏览器回归需要已安装 Chromium，使用测试数据验证读取/写入被拒绝、下载警告、恢复完整导出、重新导入以及刷新后保留记录。不要在修改真实站点内容的同时运行项目的 Admin 回归。

本功能不迁移现有存储，不需要改密码、重新登录或清理数据。需要回退代码时，先保留恢复文件和完整备份，停止本地服务，再对引入此功能的提交执行 `git revert`，重新安装锁定依赖并按项目原有方式启动；不要用清空浏览器存储作为回退步骤。线上发布和服务配置仍按各环境的独立流程处理。
